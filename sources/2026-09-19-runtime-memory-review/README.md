## Accepted result and limits

The implemented instrument supports separate fixed-primary and trainable-memory
roles, serial process isolation, source observation, immutable state snapshots,
candidate activation and restore with current corrections. The memory model learns
read/deliver actions. Archive facts, scope labels, source authority, correction
precedence and teaching targets are supplied by the controller/investigator.
Generated guidance is labeled inference; that label does not validate its content.

## Consequences for root selection

This is a functioning local example of learning evidence use, refining the
18 September preference. It also makes the next boundary concrete: **who decides
that a proposed lesson deserves acceptance, on what evidence, and at what cost?**
The runtime currently assumes that decision in source declarations and authored
teaching. Its authority guard enforces the decision; it does not discover truth.

For the [lesson-checking candidate](../../notes/FEEDBACK_DECISIONS.md#runtime-review-refinement--19-september),
use a competent stable reader first, varying the evidence used to accept candidate
lessons. Ordinary scope retrieval is suitable for this example. A new workload
must establish that lesson acceptance remains consequential after cheap checks;
the supplied authority of its correct authored rules cannot answer that question. Preserve authoritative
external corrections separately from empirical hypotheses about reusable behavior.
An investigator-owned controller can record proposals, checks and acceptance
outside the runtime, then use its existing archive/state interfaces. Autonomous
learned writing is not implemented or a prerequisite to this comparison.

The derivative's proposed varied-ID/order and independent-history training is
reasonable bounded robustness development. It should separate those changes and
evaluate on fresh histories, retaining the ordinary baseline. Root does not select
another catalog-training phase merely because it is the latest failure: the
current workload's cheap complete solution remains decisive for allocation.
