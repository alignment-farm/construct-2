v1 submitted 17 September. Exact-version API metadata are cached in

Inspected §§2–4, Limitations, and selected trajectory appendices (§§9.1–9.2,
9.5–9.6; Tables 3–4, 11–13). Results remain author-reported; no implementation

## Evidence boundary

Fixed-model component comparisons concern within-task behavior, not continuing
weight learning. Recall availability has little average benefit and often goes
unused. Planning/action comparisons are confined to T4/128k; action interfaces
also change validation support. Settings have one run per task. Token-priced
costs are proxies for locally served inference. These are conditional comparisons,
not universal component rankings. See §§2.2, 3.1–3.2 and Limitations.

## What this changes here

**Answers:** Component-level harness comparison has direct public precedent.
Our owned runtime is an instrument for such investigation; building a modular
loop by itself does not answer the Construct directive.

**Narrows:** The [database continuation](../../studies/2026-09-18-continuing-consolidation-findings.md)
observes zero fresh adapter history searches or saved-query executions. That
does not establish a retrieval defect. Missing a useful retrieval, lacking useful
material, obtaining the same information elsewhere, and failing to use information
already supplied are competing explanations. This paper does not identify which
explains our local failures. Its recall interface and persistence boundary differ
from our cross-session source history.

**Redirects:** Before selecting retrieval-oriented teaching, establish whether
better delivery of eligible prior experience helps the learner complete development
work. A diagnostic can put the relevant existing source material directly in view,
without supplying the current answer, then distinguish selection/access failure
from composition/execution failure. Investigator selection is a diagnostic
privilege, not a deployable baseline. A positive diagnostic should then face a
competent ordinary retrieval or delivery policy, with extra context and tool costs
charged, before claiming value for learned selection.

This refines the preceding preference to teach search/execution/checking. It does
not prescribe more retrieval calls or make copying a successful trajectory sufficient.
If delivered experience is unusable, investigate the learner, task composition or
teaching target. If simple delivery already works economically, added weight
learning must earn its place. Both outcomes advance the research question.

For Construct Runtime, the useful implication is experimental separability:
identify which intervention changes information delivery, stopping, action
execution or checking, and retain enough events to assess those effects. Concrete
runtime changes belong to its own project and are not commissioned by this review.
