## What was learned, and what changed

The study keeps one reported Qwen3 8B quantized model fixed and changes its output
API from flat invoice rows to a nested, ID-keyed object with an order array.
Two remedies receive the same complete source and semantic obligations:

- **D:** generate the requested API payload directly.
- **C:** extract a canonical record, then apply an exact authored adapter for
  amounts, dates and the target schema.

The retained object is a 723-byte JSON policy table. Counting 24 earlier
intervention outcomes on twelve old-interface cases yields C for plain and
correction cases, and D for precision cases. D's precision preference comes from
a predetermined tie rule: both actions succeeded on all four acquisition cases
in that category. The global acquired choice is C. Both the category policy and
fixed C succeed on all twelve acquisition cases; acquisition functions without
establishing an added decision benefit. Handwritten categories, prompts, semantic
rules and adapters remain investigator-supplied knowledge.

The policy is frozen and loaded in a new process for fresh evaluation. Root
reconstructs its counts and decisions and verifies the frozen bytes against Git
and the run manifest. This is learning through explicit retained records, with
no parameter training. Fresh comparisons replay measured alternative outcomes;
they are not live deliberative chooser-agent episodes.

## Complete outcomes after the interface change

Fresh evaluation uses eighteen new source cases on the nested interface. Each
contains two invoices and must preserve IDs, suppliers, memos, corrected amounts,
currency scales, unknown dates, cancellation and first-mention order. The complete
task is constructing the payload, not executing a payment or testing a production
service.

| Policy | Exact complete tasks | With shared source-order repair | Raw deployed requests |
|---|---:|---:|---:|
| Fixed direct D | 14/18 | 15/18 | 18 |
| Fixed canonical C | 17/18 | 17/18 | 18 |
| Inherited category policy C/C/D | 16/18 | 17/18 | 18 |
| Inherited global C | 17/18 | 17/18 | 18 |
| Current-source rule: D plain, C otherwise | 16/18 | 16/18 | 18 |
| Schema-aware ordinary reuse | 17/18 | 17/18 | 18 |
| D then C on structural invalidity | 16/18 | 16/18 | 20 |
| Retrospective best of D/C | 18/18 | 18/18 | Not deployable |

The three C-only policies coincide here; they are not independent replications.
Repair changes only the redundant order array when source IDs exactly match
emitted keys. It was developed before acquisition/fresh evaluation, is shared
across arms, and reduces fallback requests from twenty to nineteen. These repaired
scores reuse the same generations, not new trials.

**A valid payload is weaker than a faithful payload.** D is structurally valid
on 16/18 and C on 18/18, but each still has semantic failures. C extracts
`389.177 KWD` as the string `389177`; the correct adapter then scales that wrong
value. D also has a corrected-amount error, a consistently wrong identifier,
a bad order entry and malformed JSON. Root re-parses raw responses and confirms
all failures. A validator that only checks structure cannot trigger repair on
valid-looking semantic errors.

The one-case oracle advantage over fixed C shows complementary outcomes among
these two actions. It does not show that available decision observations identify
the right action, or that acquisition/observation costs repay the possible gain.
The inherited category policy avoids C's one precision error but incurs two D
precision failures. Sparse evidence and the tie rule explain the selected mapping;
they do not establish a general defect of category learning.

Nor does 16/18 on new cases establish that the interface change caused a learned
policy's degradation. Development pairs the same six cases across both interfaces
and shows D worsening from 6/6 to 3/6 while C remains 6/6. That is useful evidence
that this interface can matter. The fresh cohort is evaluated only on the new
interface; it does not isolate an average transfer effect for the chooser.
Selective recalibration, recipient-model changes and unforeseen adapter porting
are not tested. Both API contracts/adapters were available before execution.

## The stronger ordinary alternative

After those outcomes, the investigator recognized that both source sentence forms
are a closed, invertible grammar. A short source-only parser extracts every field
and explicit correction, then uses the existing adapter. It consults no gold
records, outcome table or case IDs at runtime. This is better remedy construction,
not better intervention selection.

The parser first completes 72/72 API tasks from the 36 earlier source cases as
development evidence. Code and follow-up protocol are then frozen at `9eb5073`.
On eighteen additional sources, it completes **36/36 tasks across both APIs with
zero model calls**. Root reruns the parser/adapter on every saved development and
confirmation source and checks outputs using separate integer-string amount
arithmetic. The parser also passes the published tests for known examples and
unsupported input. These checks establish the reported grammar result; they do
not measure rejection or fallback rates on natural documents.

The earlier structural unit tests had instantiated all cohort seeds, including
440, without exposing source contents or participant outcomes in their output.
The publication corrects the stronger wording “before generating” to “before
source-parser evaluation.” Git preserves the original protocol and verifies the
parser freeze before the saved follow-up results. This is fresh outcome
confirmation on new values within the same grammar, not untouched natural
language or a new acquisition history.

**Root conclusion:** once this source-only remedy is admitted, further chooser
search on these templates has no demonstrated complete-task benefit to pursue.
The nominal 18-versus-17 oracle gap was conditional on the initial action menu.
Improving the menu removes that observed gap. This is a justified explanatory
stopping point, rather than retirement after a minimally developed failed learner.
It does not prove zero selector value outside the tested grammar or distributions.

## Costs and what was verified

The study executed 84 model requests: 24 development, 24 acquisition and 36 fresh
counterfactual-action evaluations. They include ten complete-task failures,
32,180 prompt and 12,928 completion tokens, and 253.29 summed request seconds.
There were no recorded generation transport retries. These are actual experiment
costs, distinct from virtual deployment costs that charge only selected actions.

Fixed C uses 9,114 tokens on the eighteen fresh cases. The inherited category
policy uses 9,868, plus 11,868 acquisition tokens: **21,736 tokens before unmeasured
engineering cost**, with lower raw completion and equal repaired completion.
The global acquired policy has C's use cost but still pays for acquisition.
This sample supplies no repayment claim. Initial table-update time, component
engineering/maintenance, machine energy and monetary costs are unknown. Partial
investigator telemetry is separate from participant usage and is not a final
session total. D precedes C, caching is unmeasured and resource use is shared;
request times do not identify relative deployment speed.

Source parsing records roughly 0.00165 seconds for the 36 fresh tasks and no
model-use tokens. Building it and diagnosing the grammar were not free. Its
complete measured output and zero model requests do not establish lifetime
cost superiority over an unpriced engineering alternative.

Root verifies nine final source hashes and historical protocol/policy boundaries,
replays all 84 raw responses and 36 shared repairs, independently reconstructs
both sets of eight policy tables including request/token charges, and reruns
108 parser API outcomes. All nine study unit tests pass. Root uses Python 3.13.12
versus the study's reported 3.14.7. No participant generation is repeated and no
new evaluation cases are introduced. The comparison remains one model, one
schema direction, authored templates and small dependent cohorts.

## Consequences for theory and research selection

| Original expectation | Assessment from this phase |
|---|---|
| AD1 — Added intervention-choice value | **Not demonstrated; a bounded limitation is explained.** A functioning explicit chooser adds no complete benefit over ordinary fixed reuse, and a source parser removes the tested residual need. This is narrower than the original missing-evidence/use-failure comparison. |
| AD2 — Decision transfer and useful recalibration | **Partial test, unresolved overall.** Unchanged decisions cross an API change; the acquired global policy remains as effective as current schema-aware reuse. No selective recalibration, new receiving-model history or causal chooser-transfer loss is measured. |
| AD3 — Lifetime of learned access | **Unchanged.** This experiment does not test retention/revision of learned evidence access. |

The [public-method check](../sources/2026-09-29-intervention-choice-review/README.md#public-method-comparison)
adds two relevant boundaries. P126, ASlib, explicitly compares selectors with fixed
and perfect per-instance choices while charging features/probes. Its framework
narrows the interpretation of an oracle gap; it does not resolve agent-change
transfer. P127, JSONSchemaBench v3, separates constrained-generation compliance
from task accuracy. It supplies an untested ordinary remedy family for output
structure, without guaranteeing correct extracted values. Neither calls for
another generic selector benchmark or provides a validated new local workload.

The [preceding action/feedback review](2026-09-29-action-feedback-findings.md)
showed that available history can go unused and tests can omit requirements. Here,
the observations preserve a different distinction: **a faithful source can permit
an ordinary solution even when model outputs create an apparent choice problem**.
Execution checks must reflect source fidelity, and the available remedies must be
credible before the value of choosing among them can be assessed. This strengthens
the co-development account without privileging explicit code universally.

The investigator's proposed move toward independently authored language and
trustworthy labels is a reasonable direction within the existing remit. Richer
prose alone is insufficient. First determine whether competent parsing, retrieval,
validation and repair leave useful differences among remedies, and whether
available observations or earlier outcomes can help choose between them at a
useful cost. Finding no such difference is still a valid result; a positive
selector gap is not a prerequisite for accepting feasibility work. Claims
shaped by that discovery need fresh confirmation. Detailed methods remain with
the study. Other studies continue independently, and this acceptance authorizes
no duplicate study or new root-run experiment.
