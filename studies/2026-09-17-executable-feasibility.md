# Executable persistence: useful artifacts, an unresolved comparison

17 September 2026. The bounded review selected in
[executable experience](../notes/EXECUTABLE_EXPERIENCE.md) is complete.
**Select a bounded independent investigation of acquired implementation versus
reconstruction from retained procedural experience.** SkillWeaver supplies a
concrete code-generating agent and a reference-only route, but its released
defaults do not isolate this comparison. AWM's release does not supply a runnable
version of its relevant action ablation. Neither release settles cumulative
acquisition and repair cost from the inspected artifacts.

This is a recommendation for an investigator-owned question, including bounded
workload development. No additional ancillary repository or experiment is
commissioned here. The evidence-use study's accepted phase remains complete.

Inspected the author releases of AWM at

records files, hashes, static checks and limits. No author code, browser workload,
model generation or training was executed. No public success rate was reproduced.

## AWM: the relevant release path is incomplete

The Mind2Web runner accepts `--mode action` but immediately raises
`NotImplementedError` in that branch. Its workflow parser imports
`data.workflow.code.WORKFLOW_DICT`, whose module is absent from the pinned tree.
The functioning memory path inserts workflow text and scores individual actions
against recorded observations; it does not provide a complete live task sequence
with observations caused by newly generated actions. WebArena supplies a live
contextual workflow route with separate environment setup.

Thus AWM supplies a representation precedent and contextual artifacts, but not
the ready paired callable-versus-reconstruction experiment sought here. Do not
interpret this release limit as refuting the paper's results. Its table/prose
discrepancy does not need resolution to reach this feasibility decision, and the
root does not adopt a disputed numerical effect. Repairing this release is not
selected as the first investment.

## SkillWeaver: a closer starting point, with consequential defaults

The baseline already generates and executes Playwright Python. The augmented
agent can call a library using the same browser interface. `as_reference_only`
omits the library from the execution module and type-checking context, allowing
the model to generate code from the provided reference. This is a direct existing
implementation precedent; neither this switch nor code regeneration is a new
method proposed by Construct.

Five released libraries contain 438 top-level functions and the tree includes
812 WebArena task configurations. These are potentially useful donor artifacts,
not evidence that all functions currently work. Their companion verification
metadata is absent. Loading therefore creates zero test counts; the single-task
evaluator hides unverified functions by default. A nominal library run using
those files and defaults would expose no verified functions. Enabling unverified
functions provides access, but does not establish successful acquisition or
verification. Docstring usage logs are not substitutes for preserved executions.

Further implementation inspection identifies three attribution problems:

1. **The reference content depends on the route.** Production/evaluation tasks
   always call library retrieval, which returns signatures and docstrings in
   both modes. That branch ignores the reference flag when serializing content.
   Source bodies are exposed by a different non-retrieval path. Consequently the
   flag alone is not a comparison of invocation with regeneration from identical
   retained implementation. Nor are the descriptions a demonstrated sufficient
   abstraction of the original exploration experience.
2. **Primitive permissions differ.** Generated actions reject CSS locator and
   query-selector calls, whereas installed library bodies are inserted without
   that check. Static inspection finds those calls in 345 of the 438 functions.
   A library advantage could therefore include access to different primitives.
   This count measures source usage, not executed calls or successful functions.
3. **A generated step can contain extra work.** Code generation permits up to
   five correction attempts. Optional locator recovery can capture an additional
   accessibility tree and make up to five repair attempts inside execution. Both
   ordinary actions and library calls can enter recovery, but its incidence and
   work still need accounting. Equal top-level step limits do not match browser
   actions, model calls, observations or elapsed time.

The shared prompt also requires using an available matching library function
while the reference mode says functions cannot be called. A clean comparison
must resolve that instruction conflict. These are concrete conditions for reuse,
not reasons to invent a separate agent framework or require one representation
to win.

The runtime records model token usage and timing and can save `perfmon.json`.
The pinned tree contains no corresponding released acquisition/evaluation trace
collection from which this review could recover the requested cumulative
comparison. Its native records are useful starting instrumentation; historical
hard-coded dollar prices should not be treated as current costs. No changed-site
sequence with matched repairs was established by this inspection.

## What further work would change the account

The [evidence-use findings](2026-09-17-evidence-use-findings.md) make this question
more concrete: a supplied executable can remove repeated model error, but its
perfect performance says nothing about what an agent pays to acquire and retain
that implementation. Existing public evidence already establishes that agents
can acquire useful tools. The remaining comparison concerns **which acquired
object earns its continued retention**.

Distinguish two effects that our initial wording could combine:

- **Avoided reconstruction:** invoke an acquired implementation versus regenerate
  executable behavior with that same implementation available as reference.
  This isolates some invocation/regeneration work while both sides retain code.
- **Choice of retained representation:** retain implementation versus retain
  lessons, examples and failure knowledge from the same acquisition experience.
  This includes what abstraction preserves or loses as well as reconstruction.

The first cannot establish a benefit of storing code rather than text; the second
cannot attribute every difference to invocation cost. An investigator can choose
the smallest combination that identifies the consequential effect. Both should
retain competent execution, current observations and repair, with permissive
controls for useful existing tools. Tests supplied by the benchmark must not
silently become training or runtime guidance available to only one arm.

Recommend a bounded independent study using SkillWeaver as a method donor and a
small reproducible workload chosen by the investigator. Start by establishing
functioning acquired routines and a competent reconstruction alternative from
shared experience. Preserve actual acquisition evidence and price selection,
generation, execution, validation and repair. A released library may be a common
starting endowment for studying marginal use, but cannot establish acquisition
repayment without its cost and experience record. Full WebArena deployment and
live-site infrastructure are not scientific requirements if a smaller task
identifies the same question.

Stable reuse should establish whether there is anything to preserve before
revision is added. A consequential interface or meaning change can then test
whether local repair saves prior work; arbitrary breakage and unfair observation
limits are not informative substitutes. EX1–EX3 remain prospective. Do not require
all these contrasts as a large fixed grid: workload discovery, methods, feasibility
diagnosis and resource limits belong to the ancillary investigator.

This review closes on an explanatory feasibility result. Public artifacts narrow
the starting method and expose the controls needed; they do not answer the scoped
allocation question or certify novelty. The next useful contribution is bounded
experimental development of that comparison, not another generic library demo,
an AWM repair project, or an automatic extension of evidence-use training.
