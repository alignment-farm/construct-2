## What the follow-up adds

The investigator selected a database workload after inspecting alternatives,
repaired environment defects, compared a second base model, diagnosed unsuccessful
training, and pursued a source-quality continuation before fresh evaluation.
This answers the earlier autonomy concern: the investigator did useful development
within its remit instead of treating an initial null or publication as a stop rule.

The workload adapts CL-Bench's AmazonReviews-derived databases, authored questions
and schema migration. There is one constructed history, not three independent
histories corresponding to the product groups. Twelve source jobs precede a fresh
ten-job block; seven later source jobs precede another ten. A fixed base collector
supplies common histories. Both conditions retain source SQL, intermediate queries,
named executable queries, documentation and exact training records. A stale
adapter also receives the later external evidence.

Shared investigator-written views already handle physical schema changes. The
remaining problem concerns composing and completing reports, not learning that
schema repair. As the [public-method reading](../sources/2026-09-18-weight-continuation-review/README.md)
explains, this changes the learning target from the upstream benchmark. It is a
more grounded workload than the first finite invoice grammar, while still a
controlled adaptation rather than an observed continuing enterprise job.

## Acquisition, use and cost

The high-rate attempt produced invalid/repeated actions. Lower-rate training and
matched-prompt probes did not resolve acquisition. Computational SQL teaching,
together with a longer recipe, then established 12/12 source completions in both
conditions, with calls falling from 87 to 24 for the adapter. Development remained
2/6 in each condition. These bundled changes do not identify a single causal fix.
Direct execution of a stored correct source query could also avoid model calls;
87 calls is not an unavoidable cost of external reuse.

The selected recipe uses six passes, first over 24 actions and later over 38
cumulative actions. Each training run starts from base with fresh optimizer state.
Both updates and partitions were fixed before the first fresh block. Correct
results plus explicit finish within eight actions define complete tasks.

| Fresh block / condition | Correct report | Complete task | Calls |
|---|---:|---:|---:|
| Before change, external reuse | 6/10 | 4/10 | 71 |
| Before change, adapter | 4/10 | 4/10 | 33 |
| After change, external reuse | 3/10 | 3/10 | 73 |
| After change, stale adapter | 3/10 | 3/10 | 40 |
| After change, updated adapter | 2/10 | 2/10 | 42 |

The periodic strategy completes 6/20 versus 7/20 for external reuse; correct
reports are 6/20 versus 9/20. It uses 75 versus 144 calls and 124.00 versus 332.80
model seconds, but its selected training adds 438.17 seconds. Quality differs,
and training elapsed and inference time are not an interchangeable full-cost
measure. No quality-matched repayment is established. All conditions retain the
two separately tested old source obligations; these are not fresh transfer.

The complete search ledger includes 229 task executions, 1,207 calls and four
training runs totaling 516 updates / 612.19 seconds, plus source replays and
diagnostic probes. Interrupted usage is a lower bound. Investigator teaching,
engineering and upstream construction costs remain unknown.

## The teaching target and a material grading qualification

All 38 cumulative supervised actions teach submission of canonical SQL followed
by finish: 19 of each. None teaches history search or saved-query execution.
Fresh adapter runs use neither tool. The base uses 20 searches and 13 saved-query
executions across its fresh blocks. The observations are consistent with learning
a shorter direct-answer policy while failing to establish more competent use of
external experience. This is a hypothesis from the traces, not a controlled causal
comparison of teaching methods. Equal access does not mean equal evidence use.

The sole scored loss from stale to updated adapter is q112. It requests the brand
with highest average price among sufficiently large catalogs. The stale query
orders by **product count**, never price, yet returns the expected brand, Fender.
The updated query orders by average price but lacks the reference's positive-price
filter and returns Yamaha. Adding that filter reproduces Fender. The question
does not explicitly state that eligibility filter, so its interpretation also
deserves clarification before reuse.

Root replay reproduces the published grades without changing them. The one-job
score drop does **not** demonstrate forgetting a correct average-price procedure.
Answer equality on one snapshot can reward an incorrect computation; it cannot
by itself establish procedural acquisition or loss. This is an evaluation limit,
not evidence that every reported success is accidental.

## Root assessment and research direction

The original [WC1–WC3](../notes/WEIGHT_CONSOLIDATION.md#expectations-and-informative-limits)
remain intact. **WC1:** no incremental fresh-completion benefit; shorter successful
source execution is a narrower positive. **WC2:** two old obligations survive,
but there is no demonstrated useful cumulative-update advantage; supplied views
handle physical migration and q112 limits the forgetting interpretation.
**WC3:** use costs fall without demonstrated repayment at comparable quality.
One history and small dependent samples do not rank weight learning generally.

Closing this recipe's phase is reasonable after purposeful diagnosis. It does
not close the question of learning from continuing work. Root's next preference
for discussion is to test **learning how to use retained experience**, using
successful search, execution and checking behavior as teaching rather than only
final SQL. Existing P42/P89 methods already narrow this idea; a new generic
harness concept is unnecessary. Evaluation should distinguish a correct program
from a coincidentally correct result, for example with independently checked
semantics and fresh data variants that preserve the question's meaning.

A credible continuation needs a functioning development comparison, genuinely
fresh probes and eventually an independent history. It should retain competent
external reuse and account for teacher acquisition. More epochs selected against
these now-observed probes would not resolve the uncertainty. This is a research
preference, not a new commission or a requirement to seek routine root approval
for useful development already within the ancillary remit.
