## What the comparison establishes

With the full source history externally accessible, one adapter improves manual
configuration of retained reconciliation code from 3/12 to 5/12 complete tasks.
A developed contract compiler removes that observed quality advantage:

| Corrected confirmation condition | Original contracts | Revised contracts | Complete total |
|---|---:|---:|---:|
| Base model configures retained transformation | 2/6 | 1/6 | 3/12 |
| Same route plus fixed adapter | 3/6 | 2/6 | 5/12 |
| Base model uses compiler and transformation | 6/6 | 6/6 | 12/12 |
| Same compiler route plus same adapter | 6/6 | 6/6 | 12/12 |
| Direct compiler and transformation, no model | 6/6 | 6/6 | 12/12 |

The manual comparison contains three adapter-only successes and one base-only
success. It also hides an obligation regression: the revised exclusion list is
correct in 6/6 base cases but only 2/6 adapted cases. In four, the adapter retains
the old status restriction. Both preserve unknown-account quarantine and the
always-excluded void row. Complete outcomes and individual obligations are both
needed to describe revision handling.

In the compiler comparison, base uses 24 calls, 24,329 prompt tokens and 164
generated tokens with no tool errors. The adapter uses 36 calls, 38,025 prompt
tokens and 842 generated tokens, with one malformed-action repair per task.
It recovers to complete every task. Its training preceded the compiler and new
source tools; no adapter was trained specifically for the developed interface.
The traces suggest an action-convention mismatch but do not isolate its cause.

## Acquisition, correction and the stronger alternative

The study uses one synthetic history, one quantized Qwen3-4B model and one
32-update LoRA run. Eight investigator-authored, executed reference trajectories
supply sixteen supervised actions, separate from eight learner source attempts.
This is explicit teaching, not autonomous acquisition from successful experience.
Under the corrected interface, source completion is 6/8 base versus 7/8 adapted;
manual development is 1/4 versus 2/4. This is partial acquisition meeting the
declared narrow gate, not a fully acquired procedure or robust generalization.

An evidence-access audit found that the original pilot exposed only four compact
examples while training used all eight full trajectories. That comparison is
exploratory. The investigator preserved it and added public access to every exact
training row and collector trace. The same selected adapter underwent 32
source/development rechecks before 48 confirmation executions on twelve new
payloads and a base reset. No retraining or candidate reselection followed.
All arms still receive four compact examples automatically; none actually requests
a full source record in confirmation. Equal access is verified, but equal access
does not establish equal exposure or optimal retrieval.

The compiler is an investigator-written parser of the fixture generator's finite
contract grammar; the transformation is also authored. Neither was learned by the
executor. Development mattered: merely adding the compiler gave base 1/4 and
adapter 4/4; guidance to compile first, finish on success and fall back only on
error brought both to 4/4. Thus the stronger alternative includes workflow
guidance as well as code. It is a legitimate explanation of this workload's
ceiling, not evidence that arbitrary business prose can be compiled this way.

Confirmation values and payloads are new. Four configurations repeat development;
eight are absent from source/development. The configuration schedule was already
used in the exploratory evaluation. There is one history, no later source
collection, no repeated consolidation cycle and no realistic customer exports.
The broader commission is therefore only partially exercised.

## Costs and root verification

The complete record contains 172 model executions, 424 calls, 426,743 prompt
tokens, 10,626 generated tokens and 84 tool errors, including failed attempts.
The single training run processes 30,750 input positions and 944 target positions,
taking 45.51 update seconds / 50.10 total seconds. Copied confirmation manifests
do not represent another training run. In the competent compiler condition,
training and checking buy no additional completed jobs and inference work rises.
There is no observed repayment over this horizon. Authored examples, compiler
engineering, total setup and reference-execution work remain incompletely priced;
these measurements do not establish monetary break-even or controlled latency.

Root inspected instructions, brief, protocols, publication, history and selected
implementation/evidence. Its [read-only review](../scripts/review-weight-consolidation.py)
recomputed three author audits and the cost ledger, independently interpreted
contracts and regraded all 172 artifacts, checked event usage and artifact hashes,
replayed 24 direct compiler cases, and verified sixteen exact source training rows
through all four public interfaces (64 reads). It also checked 35 frozen snapshot
hashes and post-freeze confirmation execution. [Results and reading ledger](../sources/2026-09-17-weight-consolidation-review/README.md).
No model inference or training was rerun. Construct Runtime remained unchanged
at `9ffb10a66180626b80127fb1892b2cf71e39d946`; this validates a useful independent
instrument use, not every runtime capability.

## What changes at root

The [original WC1–WC3 expectations and assessments](../notes/WEIGHT_CONSOLIDATION.md#assessment-after-publication--17-september)
remain distinct. WC1 has a small manual-route gain but none against developed
compilation; WC2 has both successful explicit revision and a learned obligation
regression; WC3 has added measured work without added completion in the stronger
route. AD1 remains untested and previous AD2/AD3 assessments stand.

The [focused public review](../sources/2026-09-17-weight-consolidation-review/README.md)
adds HarnessForge (P89) and revisits P42. Existing methods already address
compatibility between policies and evolving harnesses; they narrow a possible
diagnosis rather than establish the cause here or justify inventing another
generic co-evolution loop.

This result strengthens a conditional allocation principle: assess what useful
work remains after competent explicit execution, then measure what learned
behavior contributes there. The phase closes on an explained workload limitation,
not on an adapter failing to win. Root should identify a consequential residual
decision on continuing work before selecting more runs. Retain applicable tools,
separate authored capability from capability acquired through experience, and do
not make the next synthetic task harder simply to favor weights. The enduring
directive and hybrid working hypothesis remain unchanged.
