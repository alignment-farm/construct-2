## What the program now supports

The [executive summary](../EXECUTIVE_SUMMARY.md) collects the findings. They support
three conclusions that matter together:

1. Experience can produce useful persistent behavior in records, guidance, code
   and weights. Purposeful acquisition diagnosis has yielded functioning learners;
   some learned behavior survives corrections and helps later complete work.
2. Accessibility, validity and cost determine whether that capability remains
   useful. More training, more selective maintenance or more checking can lose
   to a competent simpler procedure, even when an intermediate metric improves.
3. We have not established a broadly reliable process that turns an agent's own
   continuing work into better performance on later unfamiliar work and change.
   Many local comparisons supply the task structure, correction authority,
   appropriate routine or reference teaching that makes the remaining problem small.

The third conclusion bounds our evidence; it is not a claim that public research
has never demonstrated continuing improvement. The new
[methods comparison](../sources/2026-09-20-continuing-capability/README.md) identifies
direct precedents. Nor do strong executable alternatives invalidate learning:
the lesson-acceptance study acquired corrected SQL through model review, and
executable retention showed how retaining a reconstruction changes later costs.
Successful work that becomes routine is a useful outcome.

## The distinction that should organize the next comparison

A continuing agent leaves two related kinds of state:

- **Work products:** the current program, database, configuration, tests or other
  artifact that the next task inherits.
- **Experience about doing the work:** observations, failed attempts, reasons for
  decisions, reusable procedures, lessons and learned changes to future behavior.

These overlap. A regression test can be both a useful product and a record of a
discovered failure. The distinction identifies an experimental question, not a
required storage taxonomy. Deleting the existing program and calling the other
condition “memoryless” would confuse the value of that program with the value of
additional experience. Conversely, holding the program fixed forever would miss
benefits that experience creates through better artifacts.

Two comparisons therefore answer different questions. A **matched-workspace
diagnostic** begins from the same acquired artifact, current requirements and
ordinary tools, and varies additional eligible experience or learned state. It
asks whether that experience helps the next change. A **continuing policy
comparison** lets each policy carry forward its own work products and failures,
so better earlier decisions can help later work. It assesses the whole sequence.
Neither comparison alone attributes every source of improvement. These are
suggested contrasts for the selected question, not mandatory additions to every
study.

The central question is:

> Can accumulated experience make a later unfamiliar change more reliable or less
> costly than competent reuse of the available work products and source archive?

Here “unfamiliar” means a new obligation or combination that requires useful
adaptation, with earlier valid obligations still checked. It does not require
hiding available documentation or creating ambiguity. The agent can learn how
to investigate, modify or test a familiar kind of system even when the new
requirement is explicitly stated.

## What would make the comparison informative

The main alternative should have recoverable source experience, ordinary access,
working code and the ability to preserve useful new artifacts. Forced rewriting
and deliberately weak retrieval are already explained local confounds. Additional
curation, learned behavior or specialized access must earn its construction and
maintenance cost against that alternative. A diagnostic withholding some history
can identify information value, but it is not the full deployment comparator.

There are several plausible outcomes. Existing code and ordinary inspection may
already suffice; extra memory then adds little. Prior failed attempts or acquired
strategies may instead avoid repeated investigation and improve a fresh revision.
Experience tied to an obsolete assumption may cause harmful reuse. A useful
explanation distinguishes these outcomes and where the consequential information
survives. It need not produce a neural advantage.

Measure complete new behavior and still-valid earlier behavior throughout the
sequence, together with acquisition, checking, retrieval, training, execution
and repair costs. Changes in code complexity or memory size can be diagnostics;
they do not substitute for successful later work. Separate repeated-task recovery
from transfer to new work. Independent histories should differ in acquired
experience and required adaptation, not just identifiers or numerical seeds.
Preserve failures and use fresh confirmation after diagnostic development.

An improvement from externally authored instructions is useful engineering but
has a different provenance from an agent acquiring those instructions through
work. Record who supplies the lesson, tests, teacher trajectories and task
decomposition. A workload that the available learner cannot initially execute
needs bounded competence diagnosis before it can explain the value of persistence.

## Public research changes the selection

P88 supplies established separation of reuse and held-out generalization; P96
supplies iterative artifact evolution; P97 supplies memory-stage diagnostics.
Their [exact-version reading ledger](../sources/2026-09-20-continuing-capability/README.md)
also records limits on feedback, task selection and oracle access. Generic
longitudinal evaluation, memory diagnosis or another configurable agent loop
would duplicate established work. The selected local contribution concerns the
added useful value and cost of experience when competent artifact/source reuse
remains available through consequential change.
